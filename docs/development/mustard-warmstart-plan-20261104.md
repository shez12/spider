# Mustard 热启动：直到完成目标的执行计划

制定日期：2026-11-04；2026-11-05 修订（收敛版）；**2026-11-10 修订（见第 0 节：结果总结与调整后的计划）**。流程可按决策点改动；每次改动记录原因和证据，不改最终判据。

## 1. 研究问题与完成判据

**问题**：用前处理好的数据（示范动作和/或物理验证过的状态）热启动 RL，能否比从零更快学会原生任务，同时保留对没见过情形（原生随机初态、掉落后重新抓起）的泛化。

- **能力判据（固定评估，同一套 seed/起点）**：原生随机初态首目标到达 ≥ 50%（≥64/128）；掉落恢复 ≥ 30%（≥25/84）；在线原生回合平均完成目标数 ≥ 3。
- **效率判据（相对匹配基线）**：同一环境配置、并行规模和评估下，达到同一里程碑（原生平均完成目标数 ≥1、≥3、≥10）所需的在线帧数和墙钟时间少于从零 SAPG；单独报告离线成本（数据生成 GPU 小时、BC 时间）。
- 至少 2 个种子；只用缓存起点成功或混合奖励不算达成。
- 若匹配任务从零学不会、热启动能学会，结论改为"热启动使原本学不会的任务可学"，同样需要 2 个种子和固定评估支持。
- 预算内达不成时，交付带证据的否定结论。

### 0.2 对目标的含义

1. **能力判据没有任何一组达到。** 原生首目标最好约 0.3%（判据 ≥50%）。所有能抓起的组都卡在同一处：抓起后握不久、转不到目标朝向。
2. **在唯一可比的里程碑（原生抓起）上，状态库目前没有更快。** 原尺寸：MPPI 库 367M 帧对从零 319M 帧。小瓶：MPPI 库 262M 帧时原生抓起 0.7%，从零 156M 帧日志抬起已过 30%。都是单 seed。
3. **可靠性证据不足。** 原尺寸从零 3 次中 2 次学会抓起；带状态库原尺寸 1/1，小瓶到 270M 帧还没学会。
4. **状态库只教会了"从库内起点出发"的技能。** 右手 S/D 在缓存起点 118–125/128，从零为 0；但没有迁移到原生起点。
5. **人手管线数据（镜像库）还没有结论。** 65M 帧原生抓起 0.8%；从零组在这个帧数也只有约 1%，要到 300–400M 帧才能判断。

### 0.3 调整后的计划

**调整 1：加一个中间里程碑 M0 = 原生抓起率 ≥50%（原生起点回放）。**
原因：目标里程碑（原生平均完成目标数 ≥1/3/10）两边都是 0，效率无从比较；用户已把"随机起点抓起"定位为主结果。原判据保留，M0 只是先能比较的一级。

**调整 2：统一测量。** 每组每 500 轮（65M 帧）的存档都留一份并做原生起点回放（512 环境 × 1200 步），报告"原生抓起率首次 ≥50% 的帧数"。不再用日志抬起比例比较带状态库的组。
局限：已有的从零组没留中间存档，只有日志抬起比例；它比回放抓起率低（小瓶从零 327M 帧：日志 53%，回放 97.5%）。所以新补的从零 seed 要按同一方法留存档回放，之后才有同口径的帧数对比。

**调整 3：每组预算从 2.62B 帧降到 500M 帧。**
原因：从零学会抓起的 3 组，日志抬起过 30% 都在 156–299M 帧，500M 帧足够判 M0。省下的显存用来补 seed。每个臂只留 1 组跑长，看目标到达。

**调整 4：主对比固定为 A 场景，三个臂各 3 个 seed（42 / 7 / 新增 1 个）。**

| 臂 | 已有 | 还缺 |
|---|---|---|
| 从零 | s42r、s7、长基线（seed 42） | 1 个新 seed |
| 镜像库 delta2（人手管线数据，主角） | seed 42 在跑 | seed 7、1 个新 seed |
| MPPI 库 delta2（离线生成数据，参照） | seed 42 | 视镜像库结果决定是否补 |

**调整 5：按门槛推进，每次只改一项。**

- 门槛 1（镜像库 delta2 seed 42 到 400M 帧，预计今晚 23:00 前后）：
  - 196M 帧的存档回放抓起率已 ≥50% → 明显早于从零（s42r 同帧数日志 13%，小瓶从零 42%），支持"更快"，立即补 seed 7 和新 seed。
  - 262–393M 帧之间才到 50% → 现有数据分不出快慢，"更快"不成立，补 seed 检验"更可靠"。
  - 393M 帧存档抓起率仍低于 5% → 状态库当重置这一用法对原生抓起无效，转门槛 2。
- 门槛 2（只在门槛 1 失败时）：只改一项——状态库回合占比从 50% 降到 20%，检验"原生经验被稀释"的假设。仍无效，则按第 1 节交付带证据的否定结论，论文走分析型主线。
- 小瓶 MPPI 库 delta2：跑到 400M 帧（约 20:30）；原生抓起率仍低于 5% 就停，位置让给镜像库 seed 7。

**调整 6：只判 xyz 这条线要补一组同任务的从零对照。**
现在的 xyz 组没有可比的从零组（已有从零都带朝向和干扰力），结果无法解读。补 `从零 + 只判 xyz + 无干扰力，seed 42`。原生首目标率两组都扣同一个约 3% 的基线。这条线若两边都能到达目标，就能提供 M0 之后的目标里程碑。

**搁置（不在门槛前做）**：旋转课程、抓杆 MPPI、右手场景排查、小瓶"尺寸假设"、示范动作转左手（BC）、重建原尺寸 MPPI 库。

**论文**：大纲第 0 节的三条线（更快 / 更可靠 / 分析型）不变，走哪条由门槛 1 和补 seed 的结果决定。按现有证据，只有分析型主线有数据支持。

## 2. 当前事实（决定计划的只有这几条）

1. **匹配任务目前从零学不会**：右手 + 芥末瓶 + 关闭域随机化 + 16 秒，2.09B 帧后原生目标数约 0，σ 各 block 都约 1，奖励停在约 740。没有可学会的匹配任务，效率判据就无法计算，这是当前的第一瓶颈。
2. **与原版的差别只在用法上**（2026-11-05 对比 `/home/szc/work/newsimtoolreal`）：奖励、终止、动作、观测的代码逻辑一致；不同的是机器人（右手、自转换 URDF vs 原版左手）、物体（芥末瓶 vs 600 个程序生成工具）、域随机化（我们关闭外力/延迟/噪声）、时限（16 vs 10 秒）、并行规模（8184 vs 24576）。
3. **BC 不泛化**：数据从 503 条增加到 782 条也没有改善原生和掉落（都是约 0）。BC 学到的是记住示范，继续改 BC 数据或配方收益很低。
4. **热启动 RL 只在缓存起点上有效**：放宽探索并加课程后，抓持和接近目标起点约 127/128，原生和掉落恢复仍为 0；课程在 α=0.3 卡住。
5. **数据已经够用**：状态库 v4.1 有 3684 个去重后的状态（躺倒 1911 个，36 个水平朝向分箱全覆盖），包括机械臂随机起点的接近段。现阶段瓶颈不在数据量。
